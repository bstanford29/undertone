03Meeting notes window

New note opens this as its own window, the same way the shipped Meetings screen is its own window. Tabs use Undertone's words: Notes, Transcript, Summary. Not "Thoughts".

Window

Title

An editable field, not a label. Placeholder "Untitled note". On stop it fills with the auto title, and typing at any point wins over it.

Meta

A pulsing dot and "Recording · 12:04" while live. The dot goes flat and the line reads "Stopped · 12:41" after.

Meters

Me is the microphone. Others is the system tap, which is how AirPods work without a bot. Flat Others means the system-audio grant is off.

Summary

While recording it says it waits. After stop it shows Key points, Decisions, and Action items.

04Issue 21: know which call is on, show it with an icon, start and stop from the dock

The bar: if a Teams meeting is open, it should look like Teams. Zoom should look like Zoom. A call behind Gmail should still count. Use the Platform and Proof chips on the desk above. This is the visual spec for the detection issue.

Two channelsMe = microphone, Others = system audio tap.

Your voice

The microphone. Undertone already has this permission for dictation. It carries you and the room.

Everyone else

A Core Audio process tap copies the audio the call app sends to your output device. Headphones or speakers does not matter, the samples are the same. Permission is "System Audio Recording Only" (macOS 14.4+). Without it, Others is silent with headphones in.

Nothing joins the call

No bot, no Teams or Zoom SDK, nothing in the participant list. The call app and everyone on it never knows Undertone is recording.

What Undertone does today

Frontmost app only: native Zoom, Teams, FaceTime count; a browser counts only when the focused window title contains Meet, Zoom, or Teams. A call behind another window is invisible. The dock never auto-starts. No card. (Source: MeetingAppDetector.swift.)

The plan for Undertone

  1. Mic-owner watch. Core Audio process objects answer "which process is recording input" with a public HAL query, no new permission. Verified on a current macOS build: during playback the list named the player with output running, and it also showed com.apple.CoreSpeech holding the microphone in the background. So the watcher must map bundle IDs to known call apps and ignore system daemons, never treat "any mic user" as a call.
  2. Trigger. On macOS 26 the per-process "is running input" listeners register but never fire; a listener on the default input device's "running somewhere" property does fire, then the per-process flags are read at that moment. Fall back to a 2 s poll while a call app is running.
  3. Identify the platform. Native bundle IDs: us.zoom.xos Zoom, com.microsoft.teams2 and com.microsoft.teams Teams, com.apple.FaceTime FaceTime, com.webex.meetingmanager Webex, com.tinyspeck.slackmacgap Slack huddle. Browsers holding the mic: scan that browser's window titles through Accessibility (already granted) for Meet, Zoom, Teams, Webex tokens; Chrome's Meet tabs are titled "Meet" plus the meeting code.
  4. Icon. Native apps: the app's own icon from the bundle (NSWorkspace.icon(forFile:)). Browser calls: the browser's icon with the platform glyph in the corner. Unknown mic owner in a known browser: generic video badge.
  5. The card. Once per call, never while that call is being recorded, auto-dismiss 20 s with hover pause, Ignore remembers that call until the mic is released. Start note uses the platform name plus the window title as the meeting title.
  6. Auto-stop. When the owning process releases the mic for more than 8 s, stop and offer Resume. Mute is not release: Zoom and Teams keep the input open while muted.
  7. Out of scope for this pass: calendar Join + Start, named speakers, Automation permission for background tabs.

Proof that closes it

  • Zoom or FaceTime call on AirPods with Chrome in front, card appears with the right badge.
  • Start note, Others meter moves.
  • Leave the call, auto-stop toast.
  • Siri or dictation running does not raise a card.

06What else to change

  • Give hover an intent delay. 120ms to open and 400ms to close. Without the close delay the dock collapses when the pointer crosses the 8px gap between two controls, and the label sits outside the control it belongs to.
  • Make the nub easy to hit. 8px of drawn height is too thin to aim at. Keep the drawing at 48 by 8 and give it a 48 by 44 hit area, the same trick the Dock uses.
  • Tint the hovered control. Today every control is the same black, so hover has no feedback until the label appears. #3A3A3C reads instantly and costs nothing.
  • Use one overlay, not two. Retire the separate 240 by 44 pill. Dictation should grow out of the same dock the nub lives on, so the eye never has to find a second window. This is the biggest change in v2.
  • Add a rim on dark walls. A near-black stack on a #1B2129 desktop has almost no edge. A 1px inset rgba(255,255,255,.14) separates it without turning it into a glass card.
  • Quick note does two jobs. When a meeting is recording it appends to that meeting's Notes tab, otherwise it appends to today's Obsidian daily note. Local file either way. That is the Undertone version of a pad, instead of one more window nobody reopens.
  • Add a right-click Flow Menu. Microphone device, cleanup level, paste last result, and hide for an hour. Those settings are currently a trip to the main window, and hide-for-an-hour is the honest answer to "get out of my way" instead of quitting the app.
  • Surface mic-owner detection as the nudge. The research says Core Audio process objects on macOS 14.2 and later can answer which app holds the microphone, with no extra prompt. Undertone only checks the frontmost app today, so a Zoom call behind a browser is invisible. The nudge card is where that signal should land.
  • Let dictation run during a meeting. Today the meeting blocks it. Better: take the mic for the sentence, drop a marker in the transcript, and hand it back. A block teaches people to stop using one of the two features.
  • Label it for VoiceOver and give it keys. Every control needs a name and a shortcut: fn to dictate, Opt+M for New note, Opt+S for Quick note. Neither Opt+M nor Opt+S exists in HotkeyMonitor today.
  • Respect reduced motion. The fan-out is the one place this dock shows off. Under prefers-reduced-motion it should become a plain fade, not a slower fan.
